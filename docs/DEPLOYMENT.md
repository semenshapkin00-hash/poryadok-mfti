# Развёртывание «Порядок · SPN»

Приложение работает на CPU. Для локального запуска нужны Docker Engine с Compose v2+, 2 CPU, 2 ГиБ RAM контейнеру и запас диска для образа и данных. Приложение сохраняет минимум 5 ГиБ свободного места; перед сборкой нужен дополнительный запас. GPU, облачная LLM, токен Hugging Face и платные API не нужны.

На машине подготовки проверены Docker CLI 29.7.2 и Compose 5.5.1; локальный Docker daemon не запускался. В [первом Linux CI](https://github.com/semenshapkin00-hash/poryadok-mfti/actions/runs/43079521411) успешно выполнены сборка образа, старт контейнера, health, реальная ONNX/OCR-проверка и 94 синтетических теста. Сам job завершился ошибкой при копировании JUnit XML из tmpfs; исправленная передача отчёта пока требует нового CI-прогона. Проверка публичных реестров подтвердила наличие всех 53 закреплённых Python-версий, pnpm 11.25.0 и tesseract.js 7.0.0. Результат проверки версий: `tools/container-registry-report.json`. Размер готового образа пока не измерен.

## Локальный запуск

Выполнять из корня проекта, где лежит `compose.yaml`:

```sh
python3 tools/container_check.py --static
docker compose config --quiet
docker compose build app
```

Образ `runtime` содержит код и зависимости, но не веса и не пользовательские документы. Выберите **один** способ установки открытых весов.

С сетью, без токенов — скачиваются только шесть известных файлов из закреплённых Git revisions, каждый проверяется SHA-256:

```sh
docker compose --profile setup run --rm models-download
```

Либо без сети — если открытые веса уже лежат в `./models/semantic-minilm` и `./models/tessdata`:

```sh
docker compose --profile offline-seed run --rm models-seed
```

Вторая команда копирует только перечисленные шесть файлов, а не весь каталог `models`. Другие модели и пользовательские файлы не читаются. Обе команды заполняют volume `navigator-models`; они не получают volume с документами. Во время обычного старта скачивания запрещены: отсутствие или неверная SHA весов останавливает процесс с ошибкой.

```sh
docker compose up -d app
docker compose ps
curl --fail http://127.0.0.1:8769/api/health
docker compose exec app python tools/container_check.py --smoke
```

Открыть `http://127.0.0.1:8769`. Локальная база изначально пустая; кнопка демонстрационных документов добавляет только вымышленные примеры. `--smoke` выполняет реальную CPU-инференцию MiniLM и OCR на сгенерированной картинке «PUBLIC DEMO 123», без внутренних документов. Успешная health-проверка проверяет доступность компонентов, а smoke — их выполнение.

```sh
docker compose logs --tail=100 app
docker compose stop app
docker compose down
```

`down` сохраняет named volumes. `docker compose down -v` удаляет локальную базу, ответы, OCR-кэш и веса; использовать только при намеренном полном сбросе. Для другого локального порта: `NAVIGATOR_PORT=8770 docker compose up -d app`.

## Что воспроизводится

Python 3.12.14 и Node 24.22.1 закреплены digest официальных multi-architecture образов. Python-зависимости берутся из `requirements-lock.txt`, Node-зависимости — из `pnpm-lock.yaml` с `--frozen-lockfile`; lifecycle scripts отключены. Debian-пакеты ставятся из снимка `20261111T000000Z`. В образе сохраняются `/container-system-packages.txt` и `/container-python-packages.txt`. Файл `requirements-reasoner-lock.txt` для контейнера не используется: MLX/Metal не является Linux CPU runtime.

Веса MiniLM закреплены revision `e8f8c211226b894fcb81acc59f3b34ba3efd5f42`; Tesseract `rus+eng` — revision `87416418657359cb625c412a48b6e1d6d41c29bd`. Обе модели имеют Apache-2.0 license. Команда `python tools/container_models.py --target models` проверяет уже установленные файлы без скачивания. Название `model_qint8_arm64.onnx` сохранено для совместимости с закреплённым приложением; запуск графа на Linux amd64 и arm64 надо подтвердить smoke на целевой машине.

Установка зависимостей требует HTTPS-доступа к Docker Hub, Debian snapshot, PyPI и npm. Только отдельный setup или сборка публичного Space скачивает открытые веса с Hugging Face и GitHub. Runtime Compose подключён к `internal: true` сети без внешнего маршрута. Он не использует внешние LLM или OCR API. [Изоляция сети Compose](https://docs.docker.com/reference/compose-file/networks/#internal) и [сервисы/ограничения Compose](https://docs.docker.com/reference/compose-file/services/).

## Данные и ограничения

`.dockerignore` запрещает всё по умолчанию и разрешает только код, lock-файлы, frontend и объявленные вымышленные Markdown-примеры. `data/`, `reference/`, реальные документы, модели, `.env`, Git, host `node_modules`, виртуальное окружение и кэши не входят в build context. В Dockerfile нет `COPY . .`.

Сервис запускается UID/GID 1000, root filesystem read-only, capabilities сняты, включён `no-new-privileges`. Наружу опубликован только `127.0.0.1`, а не все сетевые интерфейсы. Named volumes:

| Volume | Назначение |
| --- | --- |
| `navigator-data` | Оригиналы, извлечённые документы и сохранённые ответы; сохраняются после перезапуска |
| `navigator-models` | Открытые закреплённые веса; у приложения read-only |
| `navigator-cache` | Временные данные локального OCR; не публикуются |

Переменные: `NAVIGATOR_PORT` меняет только host-порт Compose; `PORT` — внутренний порт; `NAVIGATOR_DATA_DIR` — каталог базы; `NAVIGATOR_REQUIRE_MODELS=1` включает обязательную проверку весов. `NAVIGATOR_BIND_HOST` допускает только `0.0.0.0` (по умолчанию внутри Docker) или `127.0.0.1` (для отдельного процесса на локальной машине). `NAVIGATOR_NODE_BINARY` и `NAVIGATOR_NODE_MODULES` внутри образа уже заданы. Не выключайте проверку моделей для демонстрации готового решения. Приложение использует один worker, чтобы согласованно обновлять локальную файловую базу.

## Публичная Docker Space: только вымышленный корпус

Для CPU-размещения предусмотрен последний Docker target `space`: порт 7860, публичные веса включаются при сборке, вымышленные документы создаются при запуске. В актуальной [документации Spaces](https://huggingface.co/docs/hub/spaces-overview) CPU Basic имеет нулевую почасовую цену, но создание Docker Space требует PRO/Team/Enterprise. Поэтому бесплатность для конкретного аккаунта надо проверить до создания; этот проект ничего не оплачивает. Не переносите туда официальные материалы конкурса, локальную базу, ответы или reference-файлы. Подготовьте отдельный публичный репозиторий с разрешённым исходным кодом; `.dockerignore` ограничивает Docker context, но **не заменяет проверку содержимого самого Git-репозитория**.

Для [Hugging Face Docker Spaces](https://huggingface.co/docs/hub/spaces-sdks-docker) в README публичного Space нужен frontmatter:

```yaml
---
title: Порядок · SPN — вымышленная демонстрация
sdk: docker
app_port: 7860
license: apache-2.0
---
```

При публикации исходный код должен включать политику `app.PUBLIC_DEMO`: разрешён только известный `SPACE_HOST`, загрузка произвольных документов и изменение вымышленной базы отключены. Entrypoint намеренно останавливается, если `NAVIGATOR_PUBLIC_DEMO=1`, а такая политика в приложении отсутствует. Docker target выставляет `NAVIGATOR_PUBLIC_DEMO=1` и `NAVIGATOR_SEED_DEMO=1`; `SPACE_HOST` предоставляется средой Spaces. Это надо подтвердить внешним smoke перед сдачей URL.

Проверка Space локально после добавления demo-политики в приложение:

```sh
docker build --target space -t mfti-navigator:space .
docker run --rm -p 127.0.0.1:7860:7860 -e SPACE_HOST=localhost mfti-navigator:space
```

Публичный Space использует `/home/app/data` с синтетическими записями. Стандартный диск Spaces считается временным: после пересоздания контейнера демо создаётся заново; сохранность пользовательских данных не обещается. Платное persistent storage здесь не подключается. Режим предназначен для проверки интерфейса и ответов по вымышленному корпусу, а не для обработки конфиденциальных документов.

## Компоненты и сценарии

Поток данных: браузер → FastAPI → локальные парсеры TXT/MD/PDF/DOCX/XLSX/изображений → фрагменты с координатами и метаданными → лексический поиск + ONNX MiniLM → проверяемые шаги, табличные факты и цитаты. Формулы XLSX не выполняются; неоднозначные и неподтверждённые значения требуют уточнения. OCR выполняет Tesseract.js WASM в локальном Node-процессе; веса и языки не скачиваются при запросе. Оригиналы и ответы хранятся только в выбранном data-volume. Если подтверждения нет, ответ сообщает о нехватке информации; несовместимые положения показываются отдельно.

1. На вымышленной базе спросить: «Как оформить командировку?». Ожидается порядок из актуальной редакции `trip_v2`, ссылки на фрагменты и явное указание редакции; устаревшая редакция не должна подменять действующую.
2. Спросить о согласовании закупки, где две вымышленные инструкции противоречат друг другу. Ожидается показ обоих источников и противоречия, без выдуманного единого согласующего. Вопрос о процедуре, которой нет в базе, должен дать сообщение о нехватке сведений.

Ограничения проверки: первый Linux CI подтвердил сборку и выполнение компонентов, но не завершился целиком успешно из-за передачи отчёта. Изменённые после него исходники и исправленный workflow требуют отдельного успешного прогона. Размер слоёв, запуск на других платформах и доступность публичного URL отдельно не подтверждены; локальный Docker daemon не запускался. OCR остаётся распознаванием с обязательной проверкой пользователем; этот контейнер не добавляет облачную генерацию и не подтверждает достоверность входного документа.
